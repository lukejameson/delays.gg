## Top 5 Concerns

### 1. [CRITICAL] Secrets Committed to Git History (curated-001)

The `.env` file containing all application secrets — database credentials (`DATABASE_URL` with `manga_user:manga_password`), the `DEBUG_API_TOKEN`, VAPID private key, session secret, and third-party API tokens (FR24, Guernsey, Aurigny) — is tracked in git and not listed in `.gitignore`. Additionally, the exact same `DEBUG_API_TOKEN` (`ac504f9dc9c07ad7d3fb53ecefe0ccecd2beab6922d0bb6eb3bc1898a8919da1`) is hardcoded verbatim in `scripts/airways-cli.sh` and `scripts/airways-cli.py`, both tracked in git. Any person with repository access can extract these credentials from the working tree or git history. The exposed `DATABASE_URL` grants direct PostgreSQL access to all tables including `users` (bcrypt password hashes) and `sessions` (session tokens). The exposed `DEBUG_API_TOKEN` unlocks all other curated findings that require the debug API — including the SQL validation bypasses that allow arbitrary database read/write. All exposed credentials must be immediately rotated and `.env` must be added to `.gitignore` and purged from git history. See: `piolium/findings-draft/longshot-curated-001-secrets-committed-to-git.md`

### 2. [HIGH] Debug API Auth Bypass via URL Encoding (curated-002)

The debug API authentication gate in `hooks.server.ts` checks `event.url.pathname.startsWith('/api/debug/')` to enforce Bearer token authentication. However, SvelteKit preserves `%2F` (URL-encoded `/`) in `pathname` while its routing engine matches encoded slashes to the same route handlers. An attacker can bypass authentication on all 17 debug endpoints — including the arbitrary SQL endpoint `/api/debug/sql` — by sending requests with `%2F` substituted for `/` (e.g., `/api%2Fdebug%2Fsql`). No token is required. Combined with the SQL validation bypasses (finding 003), this grants unauthenticated read access to all database tables including `users` and `sessions`. This bypass was verified against SvelteKit 2.21.0 source code (`routing.js` escape function). See: `piolium/findings-draft/longshot-curated-002-debug-api-auth-bypass-url-encoding.md`

### 3. [HIGH] Debug SQL: Inadequate Validation — Five Independent Bypasses (curated-003)

The `/api/debug/sql` endpoint executes user-supplied SQL via Drizzle ORM's `sql.raw()` escape hatch. The `validateSqlQuery()` function attempts to restrict queries to read-only using a naive first-token allowlist and a 7-keyword blacklist with `\b` word-boundary regex matching. This validation is structurally inadequate and can be bypassed through at least five independent techniques: (1) SQL comment injection (`IN/**/SERT` fractures keywords across `\b` boundaries), (2) PostgreSQL meta-commands (`pg_read_file`, `pg_sleep`, `pg_ls_dir`, `pg_terminate_backend`) pass validation as valid SELECT expressions, (3) `SELECT INTO` creates new tables for data exfiltration (INTO is not blocked), (4) `COPY TO PROGRAM` may achieve RCE if the database user has superuser privileges, and (5) `DO` blocks with string-split keywords evade the blacklist. An attacker with the debug token can read all user credentials, session tokens, and flight data; potentially write to or destroy database tables; and read server filesystems. See: `piolium/findings-draft/longshot-curated-003-debug-sql-inadequate-validation.md`

### 4. [HIGH] Unauthenticated Push API Endpoints (curated-004)

All `/api/push/*` endpoints — subscribe (POST), unsubscribe (DELETE), and subscription check (GET) — have no authentication whatsoever. The application's sole auth gate in `hooks.server.ts` only covers `/api/debug/*`, leaving push endpoints completely open to unauthenticated remote attackers. This enables: (1) database pollution via subscription spam, degrading query performance and skewing health monitor metrics; (2) unauthorized unsubscription of legitimate users, silently preventing them from receiving flight status notifications; and (3) privacy-violating enumeration of which push endpoints are tracking which flights. The push check endpoint exposes a boolean oracle (`subscribed: true/false`) that, combined with sequential flight ID enumeration, can build tracking profiles for any known push endpoint URL. Push endpoint URLs are capability URLs per the W3C Push API — possession authorizes sending notifications to that browser. See: `piolium/findings-draft/longshot-curated-004-unauthenticated-push-api.md`

### 5. [HIGH] Stored XSS via Airport Name in MapLibre Popup (curated-005)

Airport names are sourced from an external third-party CSV file (`ourairports-data` GitHub repository) fetched over HTTPS without integrity verification (no SRI hash, GPG signature, or checksum). The names pass through the entire pipeline — CSV → database → Svelte store → `airportName()` → MapLibre GL's `.setHTML()` — without any sanitization. The `FlightMap.svelte` component correctly uses the safe `.setText()` method for airport marker popups but uses the dangerous `.setHTML()` method for aircraft marker popups (line 124), creating an XSS injection point. A compromised upstream data source could inject JavaScript payloads into airport names that would execute in users' browsers when they view flights involving the compromised airport. The attack requires upstream data source compromise but all downstream defenses are absent. See: `piolium/findings-draft/longshot-curated-005-stored-xss-airport-name.md`
